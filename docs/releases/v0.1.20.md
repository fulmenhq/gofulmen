# gofulmen v0.1.20 – FulHash CRC + MultiHash + Verify

Release Date: 2025-11-26  
Crucible SSOT: v0.2.20

## Overview

This release closes the FulHash CRC workstream defined in `.plans/active/v0.1.20/fulhash-crc-updates.md`. We now pull the fulhash algorithms taxonomy directly from Crucible v0.2.20, add CRC32/CRC32C implementations, ship single-pass MultiHash helpers, and expose Verify utilities that understand Crucible-formatted digests. Telemetry metrics, docs, config, and schemas were synced via `make sync` so Crucible, go.mod, and embedded assets all agree.

## Key Changes

### FulHash Algorithms and Helpers

- Added CRC32 (IEEE) and CRC32C (Castagnoli) algorithms to block hashing, pooled hashers, and streaming readers.
- Implemented `MultiHash`, `MultiHashString`, and `MultiHashReader` that dedupe algorithms up front, fan out via `io.MultiWriter`, and emit bytes_hashed only once per request.
- Added `Verify`, `VerifyString`, and `VerifyReader` helpers that parse `algorithm:hex` digests, compute the requested algorithm once, and return `(match bool, error)` pairs so mismatch vs error states are distinguishable.
- Re-exported Crucible-generated `fulhash.Algorithm` constants and added `Digest.ToCrucible()` / `Digest.FromCrucible()` conversions with hex fallback when Crucible omits raw bytes.
- Added targeted tests (`fulhash/crc_test.go`, `fulhash/multihash_test.go`, `fulhash/verify_test.go`, `fulhash/digest_test.go`) to prove CRC parity, single-pass behavior, conversion round-trips, and mismatch handling.

### Telemetry & Metrics

- Added CRC32/CRC32C counters (`fulhash_operations_total_crc32`, `fulhash_operations_total_crc32c`).
- Verify helpers emit `status` + `result=match|mismatch` and a dedicated mismatch counter via `FulHashErrorsCount` with `error_type=digest_mismatch`.
- Existing bytes hashed and operation latency histograms tag `operation=multihash` or `operation=verify` for dashboard filtering.

### Documentation & SSOT Sync

- Synced Crucible taxonomy/doc assets for the fulhash module (`schemas/crucible-go/taxonomy/library/fulhash/algorithms/v1.0.0/algorithms.yaml`, updated digest/checksum schemas, metrics taxonomy, docs/standards entries, and config defaults).
- Bumped `github.com/fulmenhq/crucible` to v0.2.20 and refreshed `.goneat/ssot-consumer.yaml`, `.crucible/metadata/metadata.yaml`, `.goneat/ssot/provenance.json`, and `VERSION`.
- Updated `CHANGELOG.md` and `RELEASE_NOTES.md` with the new feature set and pruned release notes to the most recent three versions per repository convention.

## Testing & Validation

- `make check-all`
- `go test ./fulhash -run .`
- `go test ./...` (invoked by the check-all pipeline)
- Manual validation of Crucible provenance alignment (metadata, ssot-consumer, go.mod) post sync.

## Compatibility Notes

- API surface additions only (no breaking changes). Existing FulHash consumers continue to default to XXH3-128/SHA-256 unless new options are specified.
- Verify helpers adopt Crucible digest formatting, so downstream tooling can share digests across Fulmen language foundations.
- Telemetry dashboards should update to consume the new CRC counters and verify result tags.
