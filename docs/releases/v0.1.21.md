# gofulmen v0.1.21 – Signed Tags + sfetch Trust Anchor

Release Date: 2025-12-13  
Crucible SSOT: v0.2.21

## Overview

This release hardens gofulmen’s supply-chain posture for both tooling and releases.

As a pure library module, gofulmen does not publish binaries. The canonical release artifact is the **git tag**
(`vX.Y.Z`) and the source tree at that tag. Starting in v0.1.21, releases are standardized as **GPG-signed
annotated tags**, with guardrails to ensure `VERSION` matches the tag.

In parallel, `make bootstrap` now uses `sfetch` as a trust anchor and installs `goneat` using verified minisign
signatures, ensuring the SSOT sync pipeline remains high-trust.

## Key Changes

### Bootstrap: sfetch → goneat

- `make bootstrap` installs `sfetch` if needed, prints `sfetch --self-verify --json`, and runs `sfetch --self-verify`.
- `goneat` is installed via `sfetch --require-minisign` and placed in a user-space bin directory (default: `~/.local/bin`).
- Make targets no longer assume `./bin/goneat`; they resolve `goneat` from `PATH`/`BINDIR`.

### Releases: signed tag only (no artifacts)

- Added `RELEASE_CHECKLIST.md` describing the signed-tag release workflow and required environment variables.
- New Make targets:
  - `make release-provenance-check` (prints/verifies `.goneat/ssot/provenance.json` and `.crucible/metadata/metadata.yaml`)
  - `make release-tag` (creates + verifies a signed tag for `v$(cat VERSION)`)
  - `make release-verify-tag` (verifies tag signature)
  - `make release-guard-tag-version` (fails if tag != `v$(cat VERSION)`)

### Provenance visibility

`make sync` continues to manage Crucible provenance and the release workflow now makes the “check provenance”
step explicit via `make release-provenance-check`.

## Testing & Validation

- `make bootstrap`
- `make sync`
- `make tools`
- `make check-all`

## Compatibility Notes

- No API-breaking changes in library packages.
- Release authenticity now depends on signed tags (future ecosystem standardization planned for pyfulmen/tsfulmen).
