# gofulmen v0.1.28 – Config telemetry stdout hygiene

Release Date: 2025-12-28  
Crucible SSOT: v0.2.27

## Overview

This patch release fixes an output hygiene issue impacting CLI tooling and stdio-based MCP servers.

In `v0.1.27`, `config.LoadLayeredConfig*` instantiated an internal telemetry system with telemetry enabled and no emitter configured, causing JSON metrics (e.g., `config_load_ms`) to be written to stdout.

In `v0.1.28`, config loading uses `telemetry.GetGlobalSystem()` by default (disabled unless the application explicitly enables telemetry), and callers can inject a telemetry system via `LayeredConfigOptions.TelemetrySystem`.

## Key Changes

- Config loading no longer creates its own enabled-by-default telemetry system.
- Config loading uses `telemetry.GetGlobalSystem()` by default.
- Added `LayeredConfigOptions.TelemetrySystem` to allow per-call telemetry routing.
- Documented that enabling telemetry without setting `telemetry.Config.Emitter` will fall back to stdout JSON emission.
- Added regression test `TestLoadLayeredConfig_DoesNotWriteToStdoutByDefault`.

## Testing & Validation

- `go test ./config -run TestLoadLayeredConfig_DoesNotWriteToStdoutByDefault -v`
- `go test ./...`
- `make check-all`
